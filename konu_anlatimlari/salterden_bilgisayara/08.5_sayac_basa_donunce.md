# 🔁 Şalterden Bilgisayara — Ara Ders: Sayaç Başa Dönünce (CWE-190)

> Geçen derste `65535 + 1 = 0` oldu ve sen bunu bir tuhaflık olarak geçtin. Değil.
> Bu ara ders, o tek satırın arkasında **hangi matematiğin** durduğunu ve neden
> yıllardır en verimli güvenlik açığı sınıflarından birini beslediğini anlatıyor.

> Dersin bütün iddiası tek cümlede:
>
> **Makine `(ℕ, +)` üstünde değil, `(ℤ/2ⁿℤ, +)` üstünde çalışır. CWE-190,
> birincisine ait bir özelliğin ikincisinde varsayılmasıdır.**

> *(Ara ders: devre yok, yeni seviye yok. Ama sonundaki deneyler çözdüğün
> seviyelerde yapılıyor — oyunu açık tut.)*

## Makine Hangi Dünyada Yaşıyor

Herkesin kafasındaki model şu: bir değişken bir sayı tutar, sayılar sonsuza gider.

**Yanlış.** `n` bitlik bir değişkenin yaşadığı küme sonlu:

```
Uₙ  =  { 0, 1, 2, … , 2ⁿ − 1 }          eleman sayısı: 2ⁿ
```

16 bit için `U₁₆ = {0 … 65535}`. Ve bu küme **kapalı** — içinden çıkamazsın. Toplama
sonucu dışarı taşarsa, sonuç dışarıda kalmaz; **geri sarar.**

Böyle bir yapının matematikteki adı var: **`ℤ/2ⁿℤ`**, yani "tam sayılar, `2ⁿ` kutuya
bölünmüş".

Toplama da artık sıradan toplama değil:

```
makinenin toplaması  =  (a + b)  mod  2ⁿ
```

## Beş Dakikada Modüler Aritmetik

Zaten yapıyorsun: **saat.** Saat 10, üstüne 5 saat ekle → 15 demiyorsun, **3**
diyorsun. Çünkü saat 12'de dolup başa dönüyor.

### İki gösterim, karıştırılmasın

| yazım | ne | ne verir |
|---|---|---|
| `a mod m` | **işlem** — kalanı al | bir **sayı** (`0 … m−1`) |
| `a ≡ b (mod m)` | **bağıntı** — aynı kutudalar | doğru / yanlış |

```
17 mod 12 = 5              ← işlem
17 ≡ 5 (mod 12)            ← bağıntı
```

`≡` işareti "eşittir" değil, **"aynı sınıfta"** demek. Gauss 1801'de bunu bilerek
`=`'e benzer ama farklı seçmiş.

### Tanım

```
a ≡ b  (mod m)      ⟺      m  sayısı  (a − b)'yi tam böler
                    ⟺      a ile b aynı kalanı verir
```

Dikkat: `b`'nin kalan olması **gerekmiyor.** Şunların hepsi doğru:

```
17 ≡ 5 ≡ 29 ≡ −7      (mod 12)
```

Hepsi aynı kutuda: `{ … −19, −7, 5, 17, 29, 41 … }`

> 🔑 Ve buradan doğrudan 09. dersin konusu çıkıyor:
> **`−1 ≡ 2ⁿ − 1  (mod 2ⁿ)`**
> 16 bitte: `−1 ≡ 65535`. İkinin tümleyeni ayrı bir icat değil — sadece eksi
> sayıların bu çemberde nerede oturduğu.

> ⚠️ **Gösterim uyarısı:** Bazı metinler makine toplamasını `⊕` ile yazar. Güvenlik
> ve kriptografi yazılarında `⊕` neredeyse her zaman **XOR** demektir. Karıştırma —
> bu derste hep açıkça `(mod 2ⁿ)` yazıyoruz.

## Hatanın Tam Yeri

Programcının kafasındaki, hiç sorgulamadığı önerme şu:

```
∀ a, b ∈ Uₙ ,  b > 0    :    a + b  >  a          ← MONOTONLUK
```

`ℤ`'de doğru. `ℤ/2ⁿℤ`'de **kısmen** doğru:

```
(a + b) mod 2ⁿ  >  a       ⟺       a + b  <  2ⁿ
```

Yani kod **bütün girdilerde değil**, sadece şu kümede bozuk:

```
H  =  { (a, b) ∈ Uₙ × Uₙ  :  a + b ≥ 2ⁿ }
```

> 🔑 CWE-190'ı bulmanın neden zor olduğu buradan anlaşılıyor: **kodda görünür bir
> hata yok.** `n + 1` doğru yazılmış. Hata, girdilerin `H` kümesine düştüğü anda
> ortaya çıkıyor — ve testler genelde oraya hiç uğramıyor.

## İki Yön — İkincisi Daha Sinsi

| yön | ne olur | 16 bitte |
|---|---|---|
| **yukarı taşma** | büyük sayı küçüğe sarar | `65535 + 1 = 0` |
| **aşağı sarma** | küçük sayı **devasa** olur | `0 − 1 = 65535` |

Aşağı sarma pratikte daha çok can yakıyor, çünkü işaretsiz tiplerde sıfırın altı yok:

```c
size_t len = 0;
memcpy(dst, src, len - 1);   //  len-1 = 18446744073709551615
```

Bir uzunluğun sıfır olabileceği düşünülmemiş; `len - 1` bir eksilme değil, **tam tur
geri** oluyor.

## Tek Başına Zararsız

Bu önemli: CWE-190 bir **zayıflık**, kendi başına açık değil. Bir sayaç sarabilir,
hiçbir şey olmaz.

Tehlikeli olması için taşan değerin **şu dört yerden birine** gitmesi gerekiyor:

```
1.  bellek ayırma boyutu   →  malloc(n)        →  gereğinden KÜÇÜK alan
2.  sınır kontrolü         →  if (i < n)       →  kontrol DEVRİLİR
3.  döngü sayacı           →  for(; i<n; )     →  bitmez / aşırı döner
4.  dizi indeksi           →  buf[i]           →  sınır DIŞI erişim
```

> 🔑 Denetim yaparken sorulacak soru bu: **taşabilen bu sayı nereye gidiyor?**
> Dördünden hiçbirine gitmiyorsa bulgu değil, gürültüdür. Bu ayrım, iyi bir
> güvenlik raporunu gürültüden ayıran şeydir.

---

## Doğru Kontrolü Türetmek

Şu kontrol neden işe yaramaz?

```c
if (a + b > MAX)  return HATA;
```

Cevap acımasız: `a + b` **zaten sarmış** hâlde kontrole giriyor. Ve tanım gereği
sonuç hep `Uₙ` içinde, yani **her zaman** `≤ MAX`.

> ⚠️ Bu kontrol bazen kaçırmıyor. **Hiçbir zaman** tetiklenmiyor — matematiksel
> olarak özdeş biçimde yanlış bir ifade.

Doğrusunu ezberleme, **türet.** İstediğimiz `a + b ≤ MAX`. Sarmayı hiç yaptırmadan
sormak için `b`'yi karşıya at:

```
a + b ≤ MAX
a     ≤ MAX − b
```

Ve `MAX − b` **her zaman güvenli**, çünkü `b ≤ MAX` olduğundan sonuç negatif olamaz —
çıkarma hiç sarmıyor.

```c
if (a > MAX - b)  return HATA;        // taşma OLMADAN sorulmuş kontrol
```

### Çarpma için

```
a · b < 2ⁿ    ⟺    b = 0   veya   a ≤ ⌊MAX / b⌋
```

Çarpma daha tehlikeli, çünkü `H` kümesi çok daha büyük: toplamada taşmak için iki
**büyük** sayı gerekir, çarpmada iki **orta** sayı yeter.

## Ve Derleyici Kontrolünü Silebilir

C'de iki tip farklı davranıyor ve bu fark hayati:

| tip | taşma davranışı |
|---|---|
| **unsigned** | tanımlı — `mod 2ⁿ` sarar, garantili |
| **signed** | **tanımsız davranış (UB)** |

"Tanımsız" demek, derleyicinin **hiç olmayacağını varsayma hakkı var** demek:

```c
int a, b;
if (a + b < a)        // klasik taşma kontrolü
    return HATA;
```

Derleyicinin akıl yürütmesi: *"signed taşma UB, yani olmuyor. Olmuyorsa `a+b` her
zaman `a`'dan büyük veya eşit. Öyleyse bu koşul hep yanlış."*

**Ve kontrolü optimizasyonda siliyor.**

> ⚠️ Tersine mühendislikte bunu gerçekten görürsün: kaynak kodda kontrol vardır,
> disassembly'de karşılığı yoktur. Derleyici hatası değil — standardın verdiği izin.
> Bu yüzden bir binary'de "kontrol yok" demeden önce kaynağa değil, **üretilen koda**
> bakmak gerekir.

### Doğru yapma yolları

```c
if (__builtin_mul_overflow(count, size, &total)) return HATA;   // taşarsa true
buf = calloc(count, size);        // malloc(count * size) DEĞİL — calloc kontrol eder
// test ederken:  clang -fsanitize=integer
```

## CWE Nedir, Zincir Nasıl İşler

| | ne |
|---|---|
| **CWE** | zafiyetin **cinsi** — "tamsayı taşması" |
| **CVE** | belirli bir üründeki **tek bir vaka** |

CWE, MITRE'nin tuttuğu zafiyet **türleri** kataloğudur. Bir CVE açıklaması genelde
hangi CWE'ye ait olduğunu söyler.

Bizim konumuz:

```
CWE-190   Integer Overflow or Wraparound       ← bu ders
CWE-680   Integer Overflow to Buffer Overflow  ← zincirin kendi adı
CWE-787   Out-of-bounds Write                  ← sonuç
```

`CWE-680`'in varlığı ilginç: "190 bazen 787'ye yol açar" gözlemi o kadar yaygın ki
**kendi numarasını almış.** CWE'de buna *chain* deniyor — bir zafiyetin diğerini
doğurması.

Klasik kalıp, bu derste kurduğun `+1` devresinin ta kendisi:

```c
n   = 65535;
buf = malloc(n + 1);        // n+1 SARIYOR → malloc(0), sıfır bayt
for (i = 0; i <= n; i++)
    buf[i] = ...;           // 65536 kez yazıyor → sınır dışı yazma
```

> 🔑 Buradaki incelik: **sınır kontrolü yok değil, VAR.** Programcı `n + 1` kadar yer
> ayırdı, doğru düşündü. Ama *kontrolün kendisi* taştığı için küçük bir sayı görüp
> geçti. Taşma, kontrolü **devirdi.**

Gerçek dünyadan tanınmış örnek **Stagefright** (Android, 2015): medya dosyası
ayrıştırılırken boyut hesabı taşıyor, gereğinden küçük alan ayrılıyor, sonra gerçek
boyut kadar yazılıyor.

## 🎮 Oyunda Dene

Bu derste yeni seviye yok — ama **çözdüğün üç seviye**, aynı çemberin üç ayrı yüzü.
Oyunu aç ve şunları elle gör:

**1. Increment — sarma anını yakala**
```
giriş 65534  →  çıkış 65535 ,  carry-out 0
giriş 65535  →  çıkış     0 ,  carry-out 1     ← tur tamamlandı
```
Boşta bıraktığın o carry teli, çemberin başa döndüğü anı bildiriyor. Gerçek
işlemcide adı **carry flag**.

**2. Subtraction — aşağı sarmayı gör**
```
A = 0 , B = 1   →   çıkış 65535
```
Sıfırdan bir geri gittin, çemberin öbür ucuna düştün. Aynı sayı hem `65535` hem `−1`
— hangisi olduğunu **teller söylemiyor.**

**3. Less than Zero — sınırın tam yerini bul**
```
giriş 32767  →  çıkış 0     (bit 15 = 0, pozitif)
giriş 32768  →  çıkış 1     (bit 15 = 1, negatif)
```
İşaret biti sonradan konmuş bir etiket değil; **sarma sınırının geçtiği yer** tam
burası.

> 💡 Üçünü arka arkaya yaptığında şunu göreceksin: **tek bir çember var.** Increment
> onu ileri, Subtraction geri döndürüyor, Less than Zero da üstünde nerede olduğunu
> söylüyor. Üç seviye, üç farklı soru, aynı `ℤ/2¹⁶ℤ`.
