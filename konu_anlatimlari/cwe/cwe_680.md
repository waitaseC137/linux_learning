# 👾 CWE-680 — Integer Overflow to Buffer Overflow

> **Zincirin adı.** Bir program ne kadar bellek ayıracağını hesaplarken sayı
> taşar, gereğinden az yer ayrılır ve ardından o alanın dışına yazılır.

| | |
|---|---|
| **Resmî ad** | Integer Overflow to Buffer Overflow |
| **Türü** | Zincir (*chain*) — tek bir olay değil, iki olayın arasındaki bağ |
| **Öncesi** | [CWE-190](./cwe_190.md) — sayı taşar |
| **Sonrası** | [CWE-787](./cwe_787.md) — sınır dışına yazılır |
| **Nerede doğar** | [08 · Increment](../salterden_bilgisayara/08_increment.md#-güvenlik-köprüsü) |

---

## Neden Kendi Numarası Var

"190 bazen 787'ye yol açar" gözlemi o kadar yaygın ki **kendi numarasını almış.**
CWE'de buna *chain* deniyor — bir zayıflığın diğerini doğurması.

Klasik kalıp, [08. derste](../salterden_bilgisayara/08_increment.md) kurduğun
`+1` devresinin ta kendisi:

```c
n   = 65535;
buf = malloc(n + 1);        // n+1 SARIYOR → malloc(0), sıfır bayt
for (i = 0; i <= n; i++)
    buf[i] = ...;           // 65536 kez yazıyor → sınır dışı yazma
```

> 🔑 Buradaki incelik: **sınır kontrolü yok değil, VAR.** Programcı `n + 1` kadar
> yer ayırdı, doğru düşündü. Ama *kontrolün kendisi* taştığı için küçük bir sayı
> görüp geçti. Taşma, kontrolü **devirdi.**

---

## Burada İki Kutu Var

Bu zinciri üç aşamalı tek bir hat gibi çizmek yaygındır ama yanıltıcıdır. Aslında
**iki ayrı kutu** var ve ikisi de taşıyor — farklı sebeplerden:

```
   ┌──────────────────┐                      ┌──────────────────┐
   │     KUTU 1       │                      │     KUTU 2       │
   │   tam sayı       │  bu sayı BOYUT       │  ayrılan alan    │
   │   (16/32/64 bit) │  olarak kullanıldı   │  (buffer)        │
   │                  │ ───────────────────► │                  │
   │   a + b taştı    │                      │   4464 bayt      │
   │   →  4464        │                      │   ayrıldı        │
   └──────────────────┘                      └──────────────────┘
         CWE-190              CWE-680               CWE-787
      kutu 1 taştı          aradaki tel          kutu 2 taştı
     (kutu DAR olduğu    (sayı, evren           (kutu YANLIŞ ÖLÇÜYLE
      için)               değiştirdi)            kesildiği için)
```

Kutu 1 taşıyor çünkü **dar** — `2ⁿ` sınırı var. Kutu 2 taşıyor çünkü **yanlış
bir sayıya inanılarak kesilmiş.** İki ayrı olay, iki ayrı sebep.

> 🔑 **`CWE-680` üçüncü bir olay değil, aradaki telin adıdır.** Aritmetik
> dünyasından çıkan bir sayının, bellek dünyasında karar verdiği an. Kendi
> başına "olmaz" — sadece bir 787'nin sebebi bir 190'sa, rapora o etiket
> yazılır. Fren arızası kaynaklı duvar çarpması gibi: iki olay, bir dosya adı.

## Sayı Belleğe Karar Veriyorsa — Stagefright

**2015 · Android · ~950 milyon cihaz**

Bu ailenin en meşhur vakası ve yukarıdaki zincirin birebir kendisi.

Android'in medya çözümleme kütüphanesi (`libstagefright`), bir MP4 dosyasının
içindeki parça boyutlarını okuyup toplayarak ne kadar bellek ayıracağını
hesaplıyordu. Boyutlar öyle seçiliyor ki toplam **sarıyor**:

```
uzunluk = a + b          →  taştı, küçük bir sayı çıktı
tampon  = ayır(uzunluk)  →  KÜÇÜK yer ayrıldı
veriyi kopyala           →  BÜYÜK veri yazıldı
                             → tamponun dışına taşındı
```

Vakayı efsane yapan şey teknik değil, **tetikleyicisiydi:** MMS. Telefona bir
mesaj geliyordu ve Android, bildirimi hazırlamak için medyayı **kullanıcı
bakmadan önce** çözümlüyordu. Yani:

> Kurbanın hiçbir şey yapması gerekmiyordu. Dokunmak, açmak, tıklamak yok.
> Telefonun açık olması yeterliydi.

Bunun adı **sıfır tıklama (zero-click)** açığıdır ve zafiyet dünyasında en
değerli sınıftır.

Sonucu Android'in çalışma biçimini değiştirdi: MMS'in otomatik ön-indirmesi
kapatıldı, medya çözümleme ayrı ve kısıtlı süreçlere bölündü, ve Android **aylık
güvenlik yaması** takvimine geçti. O takvim bugün hâlâ Stagefright'ın mirası.

## Nasıl Önlenir

Zincirin **ilk** halkasında durdurulur — yani boyut hesabında:

```c
if (__builtin_add_overflow(a, b, &uzunluk)) return HATA;   // taşarsa true
buf = calloc(adet, boyut);     // malloc(adet * boyut) DEĞİL
```

Ayrıntısı ve neden "sonradan kontrol" işe yaramadığı:
[CWE-190](./cwe_190.md#kontrol-neden-kaybolur)
