## Which World Does the Machine Live In

The model in everyone's head is this: a variable holds a number, and numbers go on forever.

**Wrong.** The set an `n`-bit variable lives in is finite:

```
Uₙ  =  { 0, 1, 2, … , 2ⁿ − 1 }          number of elements: 2ⁿ
```

For 16 bits, `U₁₆ = {0 … 65535}`. And this set is **closed** — you cannot get out of it. If
an addition's result spills outside, the result doesn't stay outside; it **wraps back
around.**

This kind of structure has a name in mathematics: **`ℤ/2ⁿℤ`**, that is, "the integers,
divided into `2ⁿ` boxes".

And addition is no longer ordinary addition either:

```
the machine's addition  =  (a + b)  mod  2ⁿ
```

## Modular Arithmetic in Five Minutes

You already do it: **the clock.** It's 10 o'clock, add 5 hours → you don't say 15, you say
**3**. Because at 12 the clock fills up and goes back to the start.

### Two notations, don't mix them up

| written | what | what it gives you |
|---|---|---|
| `a mod m` | an **operation** — take the remainder | a **number** (`0 … m−1`) |
| `a ≡ b (mod m)` | a **relation** — they're in the same box | true / false |

```
17 mod 12 = 5              ← operation
17 ≡ 5 (mod 12)            ← relation
```

The `≡` sign does not mean "equals", it means **"in the same class"**. In 1801 Gauss
deliberately chose something that resembles `=` but isn't it.

### The definition

```
a ≡ b  (mod m)      ⟺      m  divides  (a − b)  exactly
                    ⟺      a and b leave the same remainder
```

Note: `b` **does not have to be** the remainder. All of these are true:

```
17 ≡ 5 ≡ 29 ≡ −7      (mod 12)
```

All of them in the same box: `{ … −19, −7, 5, 17, 29, 41 … }`

> 🔑 And lesson 09's subject drops straight out of this:
> **`−1 ≡ 2ⁿ − 1  (mod 2ⁿ)`**
> At 16 bits: `−1 ≡ 65535`. Two's complement is not a separate invention — it's just where
> the negative numbers sit on this circle.

> ⚠️ **Notation warning:** Some texts write machine addition as `⊕`. In security and
> cryptography writing, `⊕` almost always means **XOR**. Don't confuse the two — in this
> lesson we always write `(mod 2ⁿ)` explicitly.

## The Exact Location of the Bug

The proposition in the programmer's head, never questioned, is this:

```
∀ a, b ∈ Uₙ ,  b > 0    :    a + b  >  a          ← MONOTONICITY
```

True in `ℤ`. In `ℤ/2ⁿℤ` it's **partly** true:

```
(a + b) mod 2ⁿ  >  a       ⟺       a + b  <  2ⁿ
```

Which means the code is broken **not on all inputs**, only on this set:

```
H  =  { (a, b) ∈ Uₙ × Uₙ  :  a + b ≥ 2ⁿ }
```

> 🔑 This is where you see why this bug is hard to find: **there is no visible mistake in the
> code.** `n + 1` is written correctly. The bug surfaces only the moment the inputs land in
> the set `H` — and tests usually never go there.

## Two Directions — The Second Is Sneakier

| direction | what happens | at 16 bits |
|---|---|---|
| **overflow upward** | a large number wraps to a small one | `65535 + 1 = 0` |
| **wrap downward** | a small number becomes **enormous** | `0 − 1 = 65535` |

Wrapping downward hurts more in practice, because unsigned types have nothing below zero:

```c
size_t len = 0;
memcpy(dst, src, len - 1);   //  len-1 = 18446744073709551615
```

Nobody considered that a length could be zero; `len - 1` isn't a decrement, it's **a full
lap backwards.**

## Deriving the Correct Check

Why doesn't this check work?

```c
if (a + b > MAX)  return ERROR;
```

The answer is merciless: `a + b` enters the check **already wrapped.** And by definition the
result is always inside `Uₙ`, that is, **always** `≤ MAX`.

> ⚠️ This check doesn't merely miss sometimes. It **never** fires — it's an expression that
> is mathematically, identically false.

Don't memorise the right one, **derive it.** What we want is `a + b ≤ MAX`. To ask the
question without ever performing the wrap, move `b` to the other side:

```
a + b ≤ MAX
a     ≤ MAX − b
```

And `MAX − b` is **always safe**, because `b ≤ MAX` means the result cannot be negative —
the subtraction never wraps.

```c
if (a > MAX - b)  return ERROR;        // the check asked WITHOUT overflowing
```

### For multiplication

```
a · b < 2ⁿ    ⟺    b = 0   or   a ≤ ⌊MAX / b⌋
```

Multiplication is more dangerous, because the set `H` is much bigger: to overflow an
addition you need two **large** numbers; for a multiplication two **medium** ones suffice.

## 🎮 Try It in the Game

There's no new level in this lesson — but **three levels you've already solved** are three
different faces of the same circle. Open the game and see these with your own hands:

**1. Increment — catch the moment it wraps**
```
input 65534  →  output 65535 ,  carry-out 0
input 65535  →  output     0 ,  carry-out 1     ← the lap completed
```
That carry wire you left dangling is announcing the moment the circle returns to the start.
In a real processor its name is the **carry flag**.

**2. Subtraction — see the downward wrap**
```
A = 0 , B = 1   →   output 65535
```
You went one step back from zero and landed at the other end of the circle. The same number
is both `65535` and `−1` — and **the wires don't tell you which.**

**3. Less than Zero — find the exact location of the boundary**
```
input 32767  →  output 0     (bit 15 = 0, positive)
input 32768  →  output 1     (bit 15 = 1, negative)
```
The sign bit is not a label bolted on afterwards; it is exactly **where the wrapping
boundary passes.**

> 💡 When you do all three in a row you'll see this: **there is only one circle.** Increment
> turns it forward, Subtraction turns it back, and Less than Zero tells you where on it you
> are. Three levels, three different questions, the same `ℤ/2¹⁶ℤ`.

## Summary — Keep in Mind

```
☐ The machine runs on (ℤ/2ⁿℤ, +), not (ℕ, +). Wrapping is the rule, not the exception.
☐ a mod m = an OPERATION (a number) · a ≡ b (mod m) = a RELATION (same box or not).
☐ ≡ is not "equals", it's "in the same class". b need not be the remainder.
☐ −1 ≡ 2ⁿ−1 (mod 2ⁿ). Two's complement isn't a separate invention, it's the circle's far end.
☐ The vulnerability isn't in the arithmetic, it's in the ASSUMPTION that "addition grows".
☐ The bug set H = {(a,b) : a+b ≥ 2ⁿ}. Outside it the code is flawless — hence hard to find.
☐ Two directions: overflow upward and the 0−1 wrap downward. The second is sneakier.
☐ Do the check BEFORE the overflow: a > MAX − b. A check afterwards is IDENTICALLY FALSE.
```
