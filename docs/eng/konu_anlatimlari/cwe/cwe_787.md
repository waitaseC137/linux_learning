# 👾 CWE-787 — Out-of-bounds Write

> **Writing out of bounds.** The program writes data **past the end** of an
> allocated space, or **before its start**.

## It Overflows — But Into What?

The natural question: the buffer is `0` bytes, but the data is `65536` bytes.
**Where does that data go?**

In the physical world the answer is easy: if your box is too small, things fall on
**the floor**. The floor is empty; nobody gets hurt.

**In memory there is no floor.**

Memory is not an empty room. It is **a shelf, packed end to end with no gaps,
full all the way along.** Where your space ends, emptiness does not begin —
**someone else's space begins.**

```
 ...┌────────────┬─┬────────────┬────────────────┐...
    │  someone   │ │  someone   │    someone     │
    │ else's data│ │ else's data│   else's data  │
    └────────────┴─┴────────────┴────────────────┘
                 ↑
            your buffer
            (0 bytes — no width, but it HAS a place)
```

> 🔑 The data does not overflow into anywhere — **it writes on top of the
> neighbour.** There is no "outside" in memory. Writing outside your own bounds is
> always writing **inside someone else's**.

One more subtlety: when you ask for `0` bytes, the system does not say *"no"*. It
gives you **a valid address** — a real point on the shelf. It is just that, from
that point on, the width that belongs to you is zero. The result: the writes
**succeed**. No error, no warning, the program does not even hesitate. **The
machine does not object.**

> 💡 Think about the opposite: if the system had given no address at all, the
> program would have crashed on the first write. Ugly, but **safe** — the bug
> surfaces the moment it happens. The real danger is not the space being
> **absent**, it is the space being **real but small**. Running quietly is what
> makes it dangerous.

---

## Two Directions: Past the End and Before the Start

MITRE's definition counts both directions: *"the data is written past the end, **or
before the beginning**, of the intended buffer."*

```
   ┌─────────────────────────────┐
   │           BUFFER            │
   └─────────────────────────────┘
 ↑                                 ↑
 before the start                 past the end
 (negative index)                 (size calculation overflowed)
```

Writing **past the end** is the familiar one: the space was cut too small because
the size calculation overflowed. Writing **before the start** usually happens when
an index goes negative — the upper bound was checked and the lower bound was
forgotten. That has its own number, **CWE-839**, and the exact example sits in
[lesson 09](../salterden_bilgisayara/09_subtraction.md#-the-security-bridge).

## How It Is Prevented

An out-of-bounds write rarely arises on its own; it is almost always the result of
the previous link. So the defence is built there:

- Check the size calculation before it overflows → [CWE-190](./cwe_190.md)
- Check for zero in length subtractions → [CWE-191](./cwe_191.md)
- In index checks, look at **both the upper and the lower** bound
- Catch it at run time by building with `-fsanitize=address`
