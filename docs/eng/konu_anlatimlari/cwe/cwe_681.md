# 👾 CWE-681 — Incorrect Conversion between Numeric Types

> **Incorrect conversion between numeric types.** When a number is converted from
> one type to another, data can be lost or its meaning can change. If the result is
> used somewhere sensitive, dangerous behaviour follows.

## When the Number Decides Physics — Ariane 5

**4 June 1996 · Flight 501 · ~$370 million**

On its first flight, the European Space Agency's new rocket lost control **about 37
seconds** after lift-off and destroyed itself **at second 39**.

The head of the causal chain was a single line. In the inertial reference system
(SRI), a horizontal velocity value was being converted from a **64-bit floating
point** number to a **16-bit signed integer**.

On Ariane **4** this conversion was safe — because Ariane 4 did not go that fast
and the value always fitted in 16 bits. The code was carried over to Ariane 5
**as it was**. Ariane 5 was more powerful and accelerated harder.

```
actual value  >  32767      →  did not fit in 16 bits
```

What followed:

1. The SRI raised a conversion error and shut itself down
2. The backup SRI took over — **but it was running exactly the same software**
3. With the same data, in the same second, it shut down too
4. The flight computer read the error code as **flight data**
5. To correct a deviation that did not exist, it swung the engines to full deflection
6. The rocket broke up aerodynamically and the destruct system fired

---

## How It Differs from 190

This case is often told as "an integer overflow". Technically it is not:

```
CWE-190  →  what overflows is a CALCULATION   (a + b, a × b)
CWE-681  →  what overflows is a CONVERSION    (64-bit float → 16-bit int)
```

But the root cause is the same sentence: **the number was bigger than the box
holding it, and nobody asked.** When you are recognising cases in this family, look
for that sentence rather than the class number.

---

## Two Lessons That Have Nothing to Do with Software

**Redundancy is not redundancy if it runs the same software.** There were two
systems and one bug, and both went down at the same instant. Backup hardware that
is a second copy of the same logic dies at the same moment on the same input.

**Dead code blows up rockets.** That calculation served **no purpose at all** on
Ariane 5. It existed for pre-launch alignment and had no reason to keep running
after lift-off. It was left enabled because it had been inherited from Ariane 4.

---

## Summary — Keep in Mind

```
☐ Ariane 5: 64-bit float → 16-bit int. The value did not fit and the SRI shut down.
☐ Technically CWE-681, popularly "an overflow". Same root cause: the box was too small.
☐ An error code was mistaken for flight data. One layer misread another layer's output.
☐ A backup running the same software is not a backup.
☐ Unused code should have been removed. Dead code is not dead while it still runs.
```
