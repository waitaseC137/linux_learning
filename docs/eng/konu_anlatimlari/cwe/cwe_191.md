# 👾 CWE-191 — Integer Underflow (Wrap or Wraparound)

> **Wrapping downward.** One number is subtracted from another and the result falls
> below the smallest value that type can hold. The result is not correct — in
> unsigned types it turns into an **enormous** number.

| | |
|---|---|
| **Official name** | Integer Underflow (Wrap or Wraparound) |
| **Its upward twin** | [CWE-190](./cwe_190.md) — `MAX + 1` |
| **Where it is born** | [09 · Subtraction](../salterden_bilgisayara/09_subtraction.md) — the backward direction of the circle |
| **Its math** | [08.5 · When the Counter Wraps](../salterden_bilgisayara/08.5_sayac_basa_donunce.md) — `−1 ≡ 2ⁿ−1 (mod 2ⁿ)` |

---

## Two Directions, and the Second Is Sneakier

| direction | what happens | in 16 bits | CWE |
|---|---|---|---|
| **overflow** | a large number wraps to a small one | `65535 + 1 = 0` | [190](./cwe_190.md) |
| **underflow** | a small number becomes **enormous** | `0 − 1 = 65535` | 191 |

Underflow tends to hurt more in practice, because in unsigned types there is
nothing below zero:

```c
size_t len = 0;
memcpy(dst, src, len - 1);   //  len-1 = 18446744073709551615
```

Nobody considered that a length could be zero. `len - 1` is not a decrement, it is
**a full lap backwards**. And the number that comes out is not "a bit large" — it
is the **largest** number the type can hold.

> 🔑 Overflow needs two **large** numbers; underflow needs a single **empty**
> input. An empty list, an empty file, a zero-length packet — the inputs most often
> skipped in testing.

---

## How It Is Prevented

The same reflex: ask **before** letting the subtraction happen.

```c
if (len == 0)  return ERROR;       // or
if (a < b)     return ERROR;       // BEFORE computing a - b
```

Asking afterwards is useless, because the result arrives already wrapped. The
derivation is in
[08.5](../salterden_bilgisayara/08.5_sayac_basa_donunce.md) — the same logic as
`a > MAX - b`.

---

## MITRE's Recorded Examples

The cases listed on MITRE's CWE-191 page show the same pattern in different places:

| CVE | What happened |
|---|---|
| CVE-2004-0816 | A malformed packet leads to an underflow in a firewall |
| CVE-2004-1002 | A packet carrying an invalid length |
| CVE-2005-0199 | Long input causes the length computation to go wrong |
| CVE-2005-1891 | A malformed icon file, underflow in a loop counter |

All four share the same point: **a length that came from outside** enters a
subtraction without being checked.

---

## And One Invented Case — Gandhi

The most-told underflow story goes like this: *in Civilization, Gandhi's
aggression value is `1`; switching to democracy subtracts `−2`; `1 − 2` wraps to
`255` in an eight-bit unsigned value; and the most peaceful leader in the world
suddenly launches nuclear war.*

**The story is not true.** Sid Meier — the game's designer — wrote plainly in his
own memoir that no such bug existed. The story appeared online in the 2010s and
became legend.

The reason I stop here is not that the story is false. It is **why it is so easy to
believe.**

- The mechanism described is **real.** `1 − 2` really is `255` in unsigned 8-bit.
- The outcome is **familiar.** Everyone has seen software behave absurdly.
- And the story is **good.** A symbol of peace going nuclear is funny.

> ⚠️ You will meet this trio often while reading about security: accounts whose
> mechanism is right and whose case is invented. The correct reflex — learn the
> mechanism, **verify the case at its source.** A CVE number, a vendor bulletin, a
> CERT note, an official accident report. The four CVEs above have such a record;
> Gandhi does not.

## Summary — Keep in Mind

```
☐ 0 − 1 is 65535 in unsigned 16-bit. Not a decrement — a full lap backwards.
☐ The result is not "a bit large", it is the LARGEST number the type can hold.
☐ Overflow needs two large numbers; underflow needs a single EMPTY input.
☐ Watch for the len - 1 pattern: nobody considered the length could be zero.
☐ Do the check BEFORE the subtraction: is len == 0, is a < b.
☐ The Gandhi story is INVENTED. The mechanism is real, the case is not. Verify cases at the source.
```
