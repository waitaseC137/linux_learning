# 👾 CWE-195 — Signed to Unsigned Conversion Error

> **İşaretliden işaretsize hatalı dönüşüm.** Eksi bir sayı, eksinin bulunmadığı
> bir tipe aktarılır. Sonuç "biraz yanlış" değildir — o tipin tutabildiği **en
> büyük sayılardan biri** olur.

| | |
|---|---|
| **Resmî ad** | Signed to Unsigned Conversion Error |
| **Üst sınıf** | [CWE-681](./cwe_681.md) — Incorrect Conversion between Numeric Types |
| **Aynasi** | [CWE-196](./cwe_196.md) — ters yön |
| **Nerede doğar** | [09 · Subtraction](../salterden_bilgisayara/09_subtraction.md) |
| **Zincirdeki yeri** | [196](./cwe_196.md) → [839](./cwe_839.md) → **195** |

---

## Eksinin Olmadığı Yere Eksi Göndermek

[196](./cwe_196.md) işaretsizden işaretliye gidiyordu. Bu onun tam tersi — ve
pratikte çok daha çok can yakanı.

```c
int    n = -1;
size_t s = n;        // aynı bitler, yeni okuyucu
                     // s = 18446744073709551615
```

Yine hiçbir bit kaybolmadı. Ama işaretsiz dünyada eksi diye bir yer yok; `−1`'in
deseni oradaki **en büyük** sayıya denk geliyor.

> 🔑 Bu, [CWE-191](./cwe_191.md)'deki `0 − 1 = 65535` ile aynı yere varır, ama
> **kapısı farklıdır.** 191'de taşan şey bir **hesaptır** (çıkarma yapıldı, sonuç
> sardı). 195'te hiçbir hesap yok — taşan şey bir **dönüşümdür**. Aynı ayrım
> [CWE-190 ile CWE-681](./cwe_681.md#190dan-farkı) arasında da var: biri hesabın,
> öbürü dönüşümün taşması.

---

## Asıl Tuzak: "Hata" Değeri Boyut Olunca

MITRE'nin açıklaması tehlikenin en yaygın biçimini doğrudan söylüyor, ve bu kalıbı
C yazan herkes tanır: **birçok fonksiyon hatayı eksi dönerek bildirir.**

```c
ssize_t n = read(fd, buf, len);   // hata olursa −1 döner
memcpy(dst, buf, n);              // n burada size_t olarak okunur
                                  // −1 → 18446744073709551615 bayt
```

Hata kontrolü unutulduğunda olan şey basit bir ihmal gibi görünür. Değildir:
**hatanın kendisi silaha dönüşür.** Program yanlış gittiği anı doğru biçimde
bildirdi; o bildirimi okumayan kod, bildirimi devasa bir boyut sandı.

> ⚠️ Aynı kalıp `malloc()` tarafında da var: eksi bir değer boyut olarak
> geçirildiğinde ya çok büyük bir ayırma denemesi olur ya da sarma sonucu
> gereğinden küçük bir alan ayrılır. İkincisi
> [CWE-680](./cwe_680.md) → [CWE-787](./cwe_787.md) zincirinin kapısıdır.

## MITRE'nin Kayıtlı Örnekleri

| CVE | Ne olmuş |
|---|---|
| **CVE-2025-27363** | Bir yazı tipi işleme kütüphanesinde işaretli `short`, işaretsiz `long`a atanıyor; sarma sonucu **yetersiz** tampon ayrılıyor ve sınır dışına yazılıyor |
| **CVE-2007-4268** | Tam sayı karşılaştırmasındaki işaret hatası, yığında taşmaya izin veriyor |

> 💡 Birincisine dikkat: zincirin tamamı tek satırda duruyor — **dönüşüm (195) →
> yetersiz ayırma (680) → sınır dışına yazma (787).** Ve tetikleyicisi bir yazı
> tipi dosyası; yani kullanıcının "sadece bir belge açması" yeterli. Stagefright'ın
> MMS'i neyse, burada yazı tipi o.

## Zincirin Sonu

09. dersteki üç adımlı örnekte 195 son halka, ve tam da zararın ortaya çıktığı
yer:

```
[196]  65535 işaretli değişkene konur           →  −1
[839]  if (len > MAX) sadece tavana bakar       →  −1 geçer
[195]  memcpy uzunluğu işaretsiz okur           →  65535 bayt kopyalanır
                                                    └─► CWE-787
```

Üç numara, tek kök: **aynı desen üç kez farklı sözleşmeyle okundu.** 09. dersin
cümlesi bütün zincirin altında duruyor:

> **Desen aynı, anlam okuyanın kararı.**

## Nasıl Önlenir

```c
ssize_t n = read(fd, buf, len);
if (n < 0) return HATA;          // hatayı ÖNCE ayıkla
memcpy(dst, buf, (size_t)n);     // ancak ondan sonra çevir
```

Kural olarak:

- **Hata dönüşünü boyut olarak kullanma.** Eksi dönebilen her fonksiyonun sonucu,
  boyut/indeks yerine geçmeden önce ayıklanmalı.
- **Karşılaştırmada iki tarafın tipi aynı olsun.** C, işaretli ile işaretsizi
  kıyaslarken işaretliyi sessizce işaretsize çevirir; kıyas daha okunmadan bozulur.
- **Derleyiciye söylet:** `-Wsign-conversion` ve `-Wsign-compare` bu dönüşümleri
  görünür kılar; varsayılan olarak kapalıdırlar.
- **Çalışırken yakala:** `-fsanitize=implicit-conversion`.
